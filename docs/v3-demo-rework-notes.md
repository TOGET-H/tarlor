# V3 Demo 统一修改计划

日期：2026-05-18

## 总体目标

- 当前 Demo 面向 55 寸竖屏触控终端，按线下门店 1-2 米观看和近距离触控使用设计。
- 去掉外层设备壳，不再展示米色外框、摄像头点、外层阴影和圆角内屏。
- 页面本身是直角网页，主体直接占满浏览器视口。
- 不做购物系统，不出现价格、加购、购物车、结算、下单。
- 扫码只用于带走美学画像、推荐方案、试穿图、视频或作品集。
- 视觉和文案保持高端美学体验感，避免技术后台、规则说明、医疗诊断式表达。

## 全局导航与设置

- 全局顶栏统一为：
  - 左上：返回 / 返回首页。
  - 中间：弱化的页面提示或留空。
  - 右上：设置入口。
- 顶部角落只承载低频操作，适合放返回和设置，不放主 CTA。
- 页面主标题不再放在最顶端中间，不让顶栏承担核心页面理解。
- 页面主标题统一下沉到内容区第一屏，和核心模块放在一起。
- 顶栏中间如果保留文字，只作为弱导航提示或品牌提示，字号和视觉权重要低于内容区主标题。
- 右上角不强行放状态信息，改为设置菜单。
- 设置菜单承接：
  - 账号信息。
  - 当前门店 / 设备信息。
  - 退出体验 / 清空当前用户。
  - 主题切换。
  - 隐私说明或体验说明。
- 原来外置的演示控制器能力如主题切换，应内收进设置菜单，不在页面侧边裸露。

## 55 寸竖屏人体工学规则

- 设备总高约 190cm，屏幕底部约离地 70cm。
- 顶部 170-190cm 区间适合看标题和低频返回/设置，不适合放频繁点击的主操作。
- 底部 70-95cm 区间不放关键按钮，只用于留白、非关键说明或滚动内容延续。
- 主操作尽量落在离地约 110-155cm 的舒适触控区。
- 不采用移动端式的“标题贴顶、主按钮贴底”布局。
- 协议页、确认页、等待页、二维码弹层、设置弹层都应以中部模块呈现，避免顶部太高或底部太低。
- 二维码弹层放在屏幕中部或中上部，方便用户用手机在胸口高度扫码。
- 长列表可以滚动，但主 CTA、查看已选、生成、确认等操作必须常驻在可触达区域。

## 55 寸大屏字号规范

- 2026-05-19 重要更新：当前阶段效果优先，大屏先固定服务 `2160 × 3840` 的 55 寸竖屏尺寸，不优先考虑其他桌面尺寸适配。
- 大屏报告页可以使用固定像素布局、固定模块高度、固定字号，避免 `clamp()`、`fr`、响应式规则导致视觉不稳定。
- 后续如需适配其他尺寸，再另做 responsive 版本；移动端已经是独立页面。
- 固定 55 寸报告页建议：
  - 页面基准：`2160px × 3840px`。
  - 报告主体宽度约 `1840px`，居中。
  - 报告主体高度约 `3180px-3240px`。
  - 四个模块固定高度：
    - 基础特征：约 `760px`
    - 风格定位：约 `620px`
    - 推荐搭配：约 `920px`
    - 穿搭建议：约 `520px`
  - 模块间距约 `60px-70px`。
  - 模块标题到卡片约 `28px-32px`。
- 固定字号建议：
  - 模块标题：约 `34px`
  - 卡片标题：约 `30px`
  - 正文：约 `24px`
  - 辅助说明：约 `20px-22px`
  - 按钮：约 `24px`
- 体型 / 脸型图片必须完整显示，不裁切。
  - 图片容器白底。
  - 使用 `object-fit: contain`。
  - 图片可通过 padding / max-height 调整，但不能裁切主体。
  - 体型图尤其要避免上下被截断或视觉过长撑高卡片。

- 2026-05-19 更新：当前报告页和其他页面字号大小不统一，需要建立全局排版 token，不再按模块随意写不同 `clamp()`。
- 55 寸屏幕面向 1-2 米观看和近距离触控，字号应大于普通桌面网页，但层级必须稳定。
- 建议在 `:root` 建立统一字体 token：
  - `--fs-display`：首页品牌名 / 最高级视觉标题。
  - `--fs-page-title`：页面主标题，例如报告页、结果页、Loading 主标题。
  - `--fs-section-title`：模块标题，例如 `基础特征诊断结果`、`核心风格定位`、`场景化搭配方案`。
  - `--fs-card-title`：卡片标题，例如 `面部特征：小量感灵动型`、`风格核心元素`、`LOOK 1`。
  - `--fs-body`：正文说明、诊断点、搭配行。
  - `--fs-small`：辅助说明、色彩比例、caption、缩略标签。
  - `--fs-button`：按钮文案。
- 推荐大屏 token 范围：
  - `--fs-display`: `clamp(42px, 3.4vw, 76px)`
  - `--fs-page-title`: `clamp(30px, 2.2vw, 48px)`
  - `--fs-section-title`: `clamp(20px, 1.15vw, 28px)`
  - `--fs-card-title`: `clamp(17px, 0.95vw, 22px)`
  - `--fs-body`: `clamp(14px, 0.78vw, 18px)`
  - `--fs-small`: `clamp(12px, 0.68vw, 15px)`
  - `--fs-button`: `clamp(15px, 0.82vw, 18px)`
- 推荐行高 token：
  - `--lh-tight`: `1.2`
  - `--lh-title`: `1.3`
  - `--lh-body`: `1.55`
- 报告页字号层级：
  - 模块标题使用 `--fs-section-title`。
  - 卡片标题使用 `--fs-card-title`。
  - 诊断点、风格描述、搭配行使用 `--fs-body`。
  - 色彩比例、弱说明使用 `--fs-small`。
  - `试穿` 按钮使用 `--fs-button`，按钮尺寸由高度和 padding 控制，不靠超大字号撑开。
- 报告页具体调整方向：
  - 基础特征卡片标题和正文需要放大，正文不再像脚注。
  - 风格定位左侧 label、正文、色卡文字统一放大到可读层级。
  - 搭配方案 LOOK 标题和搭配行使用统一层级；按钮文案缩短为 `试穿`，字号不要大于卡片标题。
  - 避坑 / 优化建议不是重点，卡片标题不能突然大过前面的核心模块。
  - 总结公式标题可略强，但不超过模块标题太多。
- 全站应用范围：
  - 首页、Loading 页、自选页、试穿结果页也应逐步替换为这些 token。
  - Loading 页主标题使用 `--fs-page-title`，步骤使用 `--fs-card-title` 或 `--fs-body`。
  - 自选页商品标题、品类按钮、托盘说明统一使用 token。
  - 试穿结果页标题、缩略标签、caption、工具区使用 token。
- 移动端独立使用移动端字号规则，不直接继承 55 寸大屏字号；但视觉风格保持统一。
- 落地顺序：
  - 先在 `:root` 增加字号和行高 token。
  - 优先替换报告页所有字号。
  - 再替换 Loading、自选、试穿结果页核心字号。
  - 最后补齐移动端独立字号规范。
- 2026-05-19 补充：标题与内容间距需要统一。
  - 模块标题到卡片建议 `16px-18px`，不能贴太紧。
  - 最新倾向：大屏报告模块标题到卡片统一使用约 `18px`，最低不要低于 `14px`。
  - 模块之间建议 `20px-24px`，不能出现上方大留白、下方贴紧。
  - 卡片内部 padding 建议 `18px-22px`。
  - 卡片标题到正文建议 `8px-10px`。
  - 若一屏高度吃紧，优先压缩卡片内部行距或内容，不压缩标题与卡片之间的基本呼吸感。
  - CSS 结构建议每个模块采用 `标题行 + 内容行`，例如 `grid-template-rows: auto minmax(0, 1fr)`。
  - 后续调整：避免使用 `fr` 强行拉伸纯文字卡片导致大面积空白；报告页应采用自然高度模块 + 整体一屏排布。
  - 纯文字卡片只保留顶部和底部基础留白，不为填满高度而拉伸。
  - 图片型卡片可以保留较大的图片展示区，但文字区不应被拉伸出大片空白。

### 移动报告页

- 移动报告页有两个形态，由扫码链接携带的数据决定：
  - 无报告状态。
  - 有报告状态。
- 手机端没有用户身份信息，不支持主动查询或刷新报告。
- 扫码时链接要么带报告数据，要么不带报告数据；页面不提供 `刷新查看`、登录、手机号查询等入口。

  - 使用同大屏视觉的居中提示卡。

  - 推荐文案方向：
    - 标题：`暂未找到你的搭配诊断报告`

  - 手机端为长屏滚动，一列显示。
  - 不展示推荐方案模块，不出现 LOOK 1 / LOOK 2 / LOOK 3，也不出现 `试穿该方案`。

    - 基础特征诊断结果。
    - 核心风格定位：优雅休闲风。
    - 避坑指南与优化建议。
    - 总结：你的专属搭配公式。
  - 内容卡片、色卡、公式卡保持大屏报告的视觉语言，但按手机一列重排。

### 移动试穿结果页

- 移动试穿结果页是作品集式页面，不采用大屏端的左中右工作台。

  - 图片。
  - 视频。
  - 试穿中。
- 列表和大图预览都不显示 LOOK 标题、商品标题、场景或单品信息。
- 图片结果：
  - 列表只展示图片画面。
  - 点击后打开大图预览。
  - 大图预览支持下载图片。
- 视频结果：
  - 列表展示视频缩略画面，可用轻量播放图标表达视频类型。
  - 点击后打开视频预览。
  - 视频不支持下载，不显示下载按钮。
  - 可显示轻量提示：`视频暂不支持下载`。

  - 列表显示 loading 和 `试穿中` 文案。
  - 大图预览如展示试穿中，也只显示 loading 和 `试穿中`。

  - 图片、视频、试穿中都不显示标题和商品信息。

### 触屏交互规范

- 当前设备按触屏终端处理，不能依赖 hover 作为主要反馈。
- 全局可点击元素需要清理浏览器默认点击高亮：
  - `button`、`a`、`[role="button"]`、tab、卡片按钮、图标按钮都应去掉移动 / WebView 的蓝色 tap flash。
  - 建议使用 `-webkit-tap-highlight-color: transparent`、`touch-action: manipulation`、`user-select: none`。
- 普通触摸点击不显示蓝色 outline，但保留键盘可访问性：
  - `:focus` 不应造成触屏蓝框闪烁。
  - `:focus-visible` 可以保留明确焦点环。
- hover 样式只能作为桌面增强，不作为触屏核心反馈：
  - 主按钮、报告 `试穿`、自选商品卡、上下装切换、分类 tab、结果缩略图都必须在默认态 / 选中态 / 按压态下就能表达状态。
  - 触屏反馈以轻微按压、亮度变化、边框加重或选中底色为主，不使用悬停后才出现的关键信息。
- 推荐统一的触屏状态：
  - 默认态：边框和背景清楚，点击区域足够大。
  - 按压态：短暂 `scale(0.98)` 或亮度变化，不能造成布局跳动。
  - 选中态：背景、边框、文字颜色同时变化，不能只靠阴影。
  - 禁用态：弱化明显，并避免像“没点中”。

### 待重点调整的触屏区域

- 上下装切换：
  - 当前 `上装` / `下装` 卡片外层是透明按钮，容易出现系统蓝色点击闪烁。
  - 外层按钮需要统一 reset，选中态应由卡片自身稳定表达。
  - 点击后只出现短按压反馈，不出现蓝色 flash。
- 套装 / 上下装模式切换、分类 tab、分页按钮：
  - 统一触屏按钮样式和选中态。
  - 分页箭头的实际触控区域应不小于舒适触控尺寸。
- 报告页搭配卡片的 `试穿` 按钮：
  - 按钮默认态就要更重，作为卡片主操作。
  - 使用当前主题主强调色或主按钮色，字重提高，触控高度增加。
  - 不依赖 hover 加重；hover 只作为桌面补充。
- 扫码带走浮窗：
  - 收起态按钮和展开态关闭按钮需要更适合手指点击。
  - 关闭 / 收起入口要明显，不做很小的图标热区。
- 试穿结果缩略图列表：
  - 结果多时存在“滑动列表时误触切换”的风险。
  - 缩略图之间需要足够间距，点击和滚动反馈要清晰。
- 右侧工具按钮：
  - `title` 在触屏上不可见，不能依赖它说明功能。
  - `换背景`、`生成视频` 等工具建议增加可见短标签，或点击后给出明确状态反馈。
- 弹层关闭按钮：
  - 设置、二维码、toast、移动端预览关闭按钮都要保证足够点击面积。

## 报告页历史方案

  - 左侧：画像结论与五维解释。
  - 右侧：推荐方案预览与下一步操作。

- 报告页主容器建议固定在中部舒适区，高度控制在视口的 72%-78%，不贴地。
- 推荐区不再采用三张竖向等高大卡，否则会把主 CTA 推得过低。
- 推荐区采用 `1 张主推大卡 + 2 张次推荐小卡` 的结构，优先保证款式视觉说服力，同时控制总高度。

  - 标题区约 10%。
  - 主推卡约 38%-44%。
  - 次推卡约 24%-28%。
  - CTA 区约 12%-14%。
- `生成推荐方案试穿预览` 固定在推荐区内的中下部，不被内容自然流式推到底部。
- 左侧五维画像列表同步收紧，做成更紧凑的结论条，和右侧工作台高度对齐。
- 推荐方案是套装，不做单套逐个等待试穿。
- 点击 `生成推荐方案试穿预览` 后，一次性把 3 套推荐方案加入多套试穿生成队列。

- 左侧内容：
  - 形象状态卡：未建档时引导创建试穿形象；已建档后显示形象缩略预览。
  - 品类切换：7 个品类做成适合触控的大按钮，不再挤在右侧顶部小胶囊里。
- 右侧内容：
  - 顶部：方案托盘 + 主 CTA。
  - 主体：当前品类的大图款式卡片。
- 款式卡片改为大图卡：
  - 图片占主要面积。
  - 保留款式名称。
  - 说明压缩为短风格词或场景词。
  - 不出现价格、购物、加购。
- 未建档时可以浏览款式，但不能发起试穿。
- 未建档状态提供：
  - `前往拍照建档`
  - `使用示范模特体验`

## 已选与多套方案

- `生成试穿预览` 是自选页主按钮，放在右侧款式区顶部，不放左侧小卡片，也不放页面底部。
- 主按钮和当前已选方案绑定，例如：`方案 A · 已选 3/4` + `生成试穿预览`。
- 已选内容默认收起为方案托盘，避免挤压款式大图。
- 点击 `查看已选` 后，在右侧顶部展开中等高度面板：
  - 显示当前方案内的已选单品。
  - 支持删除单品。
  - 支持清空当前方案。
  - 支持保存为一套方案。
- 支持多套方案：
  - 当前编辑方案最多 4 件。
  - 用户可保存为 `方案 A / 方案 B / 方案 C`。
  - 最多保存 3 套方案。
  - 保存多套后，主按钮改为 `生成 2 套试穿预览` 或 `生成 3 套试穿预览`。
- 多套方案管理仍放在右侧顶部方案托盘中，不做购物车式侧栏，也不放到底部。

## 统一多套试穿流程

- 推荐页和自选页进入同一套多套试穿生成流程，不维护两套结果页面。
- 报告页来源：系统推荐 3 套方案。
- 自选页来源：用户保存的 1-3 套自选方案。
- 真实试穿预计 1-2 分钟，因此不做点击商品立即换装。
- 统一流程：
  - 选择或确认 1-3 套方案。
  - 点击生成试穿预览。
  - 进入多套试穿生成中。
  - 进入试穿结果对比页。
- 多套生成等待页根据来源展示不同标题：
  - 推荐来源：`正在生成推荐方案试穿预览`
  - 自选来源：`正在生成自选方案试穿预览`
- 等待页不显示具体 `方案 A / 方案 B / 方案 C` 的生成步骤，避免推荐、自选、不同数量方案之间不通用。
- 等待页步骤改为通用美学生成阶段：
  - `读取专属形象`
  - `理解搭配层次`
  - `生成试穿画面`
  - `优化面料光影`
  - `整理结果作品`
- 等待页也遵守中部模块原则，不把主信息挤到顶部或底部。

## 试穿结果与二次创作

- 试穿结果页统一承接推荐试穿和自选试穿。
- 试穿结果页不是单纯终点页，同时承担轻量影像工坊能力。
- 不再单独跳转到一个重型 `AI 影像工坊` 页面。
- 结果页采用左中右三段式结构，不采用左窄列表 + 右窄图，也不采用两张窄竖卡片布局。
- 结果页结构：
  - 左侧 12%-14%：结果缩略列表，只放缩略图和短标签。
  - 中间 58%-60%：当前选中结果主画布，只展示画面，可放很轻的状态标签，不叠加按钮。
  - 右侧 26%-28%：二次创作操作和扫码带走。
- 右侧不显示当前结果详情，不重复展示当前标题和说明。
- 当前结果标题如需显示，只能作为中间主画布内的轻量状态标签，不能成为右侧信息块。
- 换背景、生成视频、生成大片、扫码带走都放在右侧中部操作区，不覆盖试穿图，不贴底。
- 结果列表卡片只保留缩略图和短标签，避免文字拥挤。
- 多套结果采用“主预览 + 结果卡片列表”，避免三张全身图平均挤小。
- 对单个试穿结果进行二次操作时，不跳出当前页面。
- 二次操作完成后，在当前结果列表中追加新结果，例如：
  - `方案 A · 原始试穿`
  - `方案 A · 艺术馆背景`
  - `方案 A · 秀场视频`
- 二次创作只围绕图像和视频，不出现购物相关能力。

## 扫码带走

- 二维码能力统一定义为“带走结果”，不用于下单。
- 报告页二维码入口：
  - 按钮文案：`扫码带走美学画像`
  - 支持带走美学画像。
  - 支持带走推荐方案。
  - 可选支持稍后在手机继续查看推荐方案。
- 试穿结果页二维码入口：
  - 按钮文案：`扫码带走结果` 或 `扫码带走作品集`
  - 支持带走当前试穿图。
  - 支持带走多个试穿结果组成的作品集。
  - 视频生成后也通过同一入口带走。
- 二维码不巨大常驻，统一由按钮触发浮层。
- 二维码浮层放在屏幕中部或中上部，不贴底。
