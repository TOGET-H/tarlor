# GitHub CI

工作流：`.github/workflows/ci.yml`。用户已选择 **只自动检查，服务器保持手动部署**。

## 触发方式

- 向 `main` 推送提交。
- 创建或更新 Pull Request。
- 在 GitHub Actions → CI → Run workflow 手动触发。

同一分支的新任务会取消尚未完成的旧检查。流程仅申请 `contents: read` 权限，不使用服务器 SSH 凭证或阿里云凭证，不操作生产服务器，不向外部模型发起付费请求。

## 检查内容

1. Ubuntu 22.04、Node.js 22.23.3、pnpm 9.14.4，按锁文件安装依赖。
2. 生成 Prisma 客户端和 Nuxt 类型。
3. TypeScript 类型检查、AI 通道契约测试（假传输，不访问供应商）和生产构建。
4. 在 runner 临时 SQLite 数据库中运行迁移并初始化 78 张牌。
5. 启动生产构建，测试首页、牌库、抽牌页面及牌图；验证单牌与三牌抽取、通道目录、模拟解读元数据和无效输入处理。
6. 使用本机假上游验证生产环境变量覆盖、实际 HTTP 通道分派和严格错误模式，不连接真实模型供应商。
7. 语音控制与 TTS 网关单测使用假音频、假供应商验证播放生命周期、并发限制和缓存，不请求微软语音服务。

CI 使用 `/tmp/oracle-ci.db`，不会访问服务器上的 `/var/lib/digital-oracle/oracle.db`。Action 引用固定提交 SHA，Node/pnpm 版本与现有服务器一致。

## 手动发布

CI 成功仅代表仓库代码检查通过，不代表已发布，也不代表服务器与仓库完全一致。实际服务器仍运行当前已部署版本。需要上线时，再单独上传版本、构建、备份数据库并发布。

仓库尚未配置强制分支保护；CI 本身不会阻止有权限的用户绕过失败检查直接推送。
